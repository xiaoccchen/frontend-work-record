## 项目专属规则

### 验证策略（成本分级）

验证手段按成本从低到高排，默认从最低一级开始，够用就停：

- **L0 静态检查**（无条件必跑）：`npx tsc -b; npx eslint .`，两者均需零报错。
- **L1 确定性脚本**（默认主力）：凡能用脚本算出确定数值或布尔值的，写脚本，不要动用浏览器子代理。
  - 样式 / 间距 / 尺寸：用 CDP 或 playwright 在真实页面读 `getComputedStyle`，打印或断言具体数值，不靠「看起来对不对」。
  - 纯逻辑：总结排序、备份 `schemaVersion`、desktop 与 local 双实现返回值一致性，直接断言。
  - 脚本为一次性临时文件，用完即删，不入库。
- **L2 浏览器子代理**（例外，非默认）：仅在下列情况使用——
  - 关键交互链路：多步用户操作、跨页面 / 跨 store / 跨 IPC（如 录入 → 保存 → 列表刷新 → 总结生成）。
  - L0 / L1 原理上覆盖不到的表现层问题：布局塌陷、遮挡。
  - 已知只能靠真实点击的场景（如 antd `RangePicker`）。

约束：

- 动用 L2 前，先在回复里说明「L0 / L1 为什么不够」，再调子代理。
- 同一任务对同一 URL 的浏览器子代理调用不超过 2 次，超出先停下与用户对齐。
- 汇报验证结果时必须标注实际用了哪一级；L0 通过不等于功能已验证。
